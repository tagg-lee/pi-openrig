AI 팀으로 영상 만들기

사람은 대화창 하나에서 말합니다. 그 뒤의 일은 AI 팀이 나누어 하고, 결과와 질문을 같은 대화창으로 가져옵니다. 이 문서는 그 구조를 설명합니다.

한 문장 요약: 사람은 창구(pi)와만 대화합니다. 창구는 일을 관리자(lead)에게 넘깁니다. 관리자는 제작(editor)과 검사(qa)에게 일을 나눕니다. 끝나면 관리자가 결과를 창구로 보내고, 창구가 사람에게 보여 줍니다.

1등장인물 넷 (+ 사람)

각자는 AI 대화창 하나입니다. 대화창마다 맡은 일이 정해져 있습니다.

사람

태극 님

  • 원하는 것을 말합니다
  • 결과를 보고 피드백합니다
  • 결정할 것을 고릅니다
A · 창구

pi

  • 사람과 대화합니다
  • 요구를 구체적으로 정리합니다
  • 일을 관리자에게 넘깁니다
  • 보고를 쉽게 바꿔 보여 줍니다
B · 관리자

lead (Claude)

  • 일을 작게 나눕니다
  • 동시에 할 수 있으면 사람을 늘립니다
  • 결과를 하나로 모읍니다
C · 제작

editor (Claude)

  • 컷 편집, 자막, 모션, 렌더
  • 파일을 쓰는 유일한 자리
D · 검사

qa (Codex)

  • 측정하고 검사합니다
  • 보고서만 씁니다
  • 필요할 때만 켭니다

2일이 흐르는 순서

예: "D 후보로 자막을 넣어 줘"라고 말했을 때.

  1. 사람 → 창구: 원하는 것을 말합니다.
    "D로 가고, 자막은 얼굴 아래, 폰트는 Pretendard로."
  2. 창구: 빠진 것을 묻고, 일을 구체적으로 정리합니다.
    "자막 길이 기준은 기존 규칙(줄당 16자)을 따를까요?" → 정리한 요청서를 만듭니다.
  3. 창구 → 관리자: 요청서를 관리자에게 넘깁니다.
    사람은 이 단계를 보지 않아도 됩니다.
  4. 관리자: 일을 나누어 제작과 검사에게 맡깁니다.
    자막 파일 만들기 → 제작. 자막 규칙 검사 → 검사. 일이 많으면 제작을 2명으로 늘립니다.
  5. 제작·검사: 각자 일을 하고 관리자에게 결과를 보냅니다.
  6. 관리자 → 창구: 결과를 하나로 모아 보냅니다. 사람이 정해야 할 것이 있으면 질문도 함께 보냅니다.
    "프리뷰 v10 완료. 볼 파일: …mp4. 결정할 것: 출처 문구를 처음에도 넣을까요?"
  7. 창구 → 사람: 짧게 요약해서 보여 줍니다. 질문은 선택 창으로 띄웁니다. 사람이 고르거나 피드백하면 1번으로 돌아갑니다.

3rig · pod · seat 뜻

OpenRig는 AI 대화창 여러 개를 하나의 팀으로 묶는 도구입니다. 회사에 비유하면 이렇습니다.

OpenRig 용어비유이 구조에서
rig프로젝트 팀 하나영상 1편 = rig 1개. 영상이 끝나면 팀을 해산합니다.
pod팀 안의 부서관리 부서(orch), 제작 부서(build), 검사 부서(review)
seat책상 하나 = 사람 한 명lead, editor, qa. 각각 AI 대화창 하나입니다.
주소책상의 내선 번호부서-이름@팀. 예: orch-lead@d2-shorts
큐업무 요청서 보관함일을 맡길 때 쓰는 기록. 아래 5번에서 설명합니다.

4제안한 팀 구성

영상 1편의 rig입니다. 부서는 역할로 나눕니다. 일이 많으면 같은 부서 안에서 책상(seat)을 늘립니다.

rig: 영상 1편 (예: d2-shorts)
pod orch · 관리 부서
A · 창구 (pi)orch-pi@… · 사람과 대화
B · 관리자 (lead)orch-lead@… · 나누고 모음
pod build · 제작 부서
C · editorbuild-editor@… · 유일하게 파일을 씀
+ editor2 (필요할 때만)병렬 작업 · 쓰는 파일이 겹치지 않게
pod review · 검사 부서
D · qareview-qa@… · 필요할 때만 켬

지금 d2-shorts는 부서가 하나(studio)이고, 그 안에 lead·editor·qa가 있습니다. 창구 자리는 없습니다.

5큐: 일을 주고받는 방법

AI끼리 일을 주고받는 방법은 두 가지입니다. 이 구조는 큐를 씁니다.

👋

send: 어깨 두드리기

상대 대화창에 글자를 바로 입력합니다.

기록이 남지 않습니다. 상대가 다시 시작하면 사라집니다. 짧은 알림용입니다.

📋

queue: 업무 요청서

요청서를 보관함에 넣고, 상대를 깨웁니다.

누가 맡았는지, 끝났는지 기록이 남습니다. 다시 시작해도 남아 있습니다. 실제 일은 이것으로 주고받습니다.

요청서에는 상태가 있습니다: 대기 → 맡음(claim) → 끝남(done) 또는 다음 사람에게 넘김(handoff).

6pi-openrig가 하는 일

문제가 하나 있었습니다. 관리자(B)가 창구(A)에게 요청서를 보내도, 일반 pi 대화창은 그것을 알 수 없었습니다. 그래서 창구가 먼저 묻기 전에는 보고를 받지 못했습니다.

pi-openrig는 이 문제를 해결하는 pi 확장입니다. 다음 세 가지를 합니다.

  1. 자리 잡기: 대화창에 /rig attach d2-shorts를 입력하면 이 대화가 팀의 창구 자리(orch-pi@d2-shorts)가 됩니다.
  2. 받기: 누가 이 주소로 요청서를 보내면, 1초 안에 대화창에 메시지로 들어옵니다. 결정 질문이면 선택 창이 뜹니다.
  3. 보기: 화면 아래 상태줄에 팀원이 일하는 중인지, 쉬는지 표시됩니다.
── 보고가 들어올 때 ── [rig 큐 qitem-…] orch-lead@d2-shorts → orch-pi@d2-shorts 제목: 프리뷰 v10 완료 볼 파일: media/renders/preview-v10-D.mp4 … ── 결정 질문이 들어올 때 ── [orch-lead@d2-shorts] 자막 폰트 결정 (1/1) 자막 폰트? → Pretendard (추천) LINE Seed 직접 입력… 나중에 (대화로 넘기기)
rig orch-pi@d2-shorts · orch-lead● build-editor○ review-qa·

위: 대화창에 보이는 모습. 아래 줄: 상태줄 (● 일하는 중, ○ 쉼, ! 확인 필요, · 꺼짐)

사람이 선택하면, 그 답이 자동으로 관리자에게 돌아갑니다. 관리자는 답을 받고 일을 이어 갑니다.

7지금 된 것과 안 된 것

됨

연결 도구 (pi-openrig)

만들어서 이 맥의 pi에 설치했습니다. 실제 Claude 관리자와 질문 → 선택 → 답 받기까지 시험했습니다.

아직

팀 구성 파일 (rig.yaml)

위 4번의 부서 셋 구조로 된 rig 파일이 없습니다. 지금 d2-shorts는 부서 하나 구조입니다.

아직

관리자 지침

관리자(lead)는 창구 주소를 모릅니다. "보고는 창구로 보낸다", "결정은 질문 블록으로 묻는다"를 관리자의 역할 문서에 적어야 합니다.

정리하면, 연결선은 깔았지만 팀은 아직 그 선을 쓰도록 짜여 있지 않습니다.

8적용하려면 할 일

  1. 어느 영상에 먼저 쓸지 정합니다. 지금 편집 중인 d2-shorts, 또는 다음 새 영상.
  2. 팀 구성 파일을 고칩니다. 관리·제작·검사 세 부서로 나눕니다. 관리자 지침에 창구 주소와 질문 방법을 넣습니다.
  3. 팀을 켜고 창구를 연결합니다. pi 대화창에서 /rig attach <영상 rig>를 입력합니다.
  4. 이 대화창에서만 말합니다. 관리자 창에는 직접 입력하지 않습니다. 두 곳에서 동시에 지시하면 지시가 섞입니다.
⚠ 부서를 바꾸면 자리 주소가 바뀝니다 (예: studio-lead → orch-lead). 그래서 팀을 다시 켜야 합니다. d2-shorts처럼 작업 중인 영상은 바꾸는 동안 잠시 멈춥니다. 다음 새 영상부터 적용하는 것이 가장 간단합니다.
